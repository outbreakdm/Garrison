Haiku for questions, Sonnet for drafts

Questions already run on Haiku, because everything does today (QM_MODEL defaults to claude-haiku-5-5). So the proposal comes down to one change: moving drafts to Sonnet. With the same token counts, a Sonnet draft costs about 20× more than a Haiku draft. Your supplies system means Garrison's margin stays protected, so admins pay the difference in fewer messages instead. Questions on Haiku also aren't cheaper than drafts: thinking is most of the output either way.

Supplies

Admins pay for it in messages

A supply is $0.001 of AI, charged at what the call really cost, so Garrison's margin holds whatever model you use. What changes is how far a pool goes. A Sonnet message also holds 270 supplies while it runs (three rounds at the output cap), against 14 on Haiku. That's more than a Free person's whole 200-supply month, so every Free message on Sonnet would drop to two rounds or a short answer.

Time

Reply time follows output length, plus a fixed wait

How a message would be routed

The model decides to draft inside the call

Today one structured call returns a reply and, optionally, a plan (planner.ts, chat()). To use Sonnet only for drafts, Garrison has to know ahead of time, or find out afterwards.

  1. Haiku first, Sonnet on a draft. Questions cost nothing extra. A draft pays for both models and waits for both calls back to back, and the prompt cache doesn't carry over, because caches belong to one model.
  2. A small routing call. A short, low-effort Haiku call labels the message first. It adds a round trip and a tiny cost to every message, and labels some messages wrong.
  3. The admin chooses. A "Draft it" button, or a draft mode, sends the message to Sonnet. It costs nothing and adds no wait, but it changes how the chat works.
Recommendation

Keep Haiku for drafts until an eval shows it falling short

Production shows no quality problem with Haiku: no draft failed Garrison's checks, and 5 of 8 were applied. Switching drafts to Sonnet means roughly 13× the AI per message and about a tenth of the messages in a Pro pool, and it probably makes drafts slower. Two cheaper steps come first:

  1. Run questions at low effort on Haiku. It's one setting change, and since output is most of the reply time, it should shorten question replies. It needs a quick check that answers stay good.
  2. Measure before deciding. Run 20 realistic messages on both models, 3 times each, and record reply time, output tokens, whether the draft passes Garrison's checks, and whether it does what was asked. That's about $2.80 of API calls, and needs an Anthropic API key, which this machine doesn't have.
